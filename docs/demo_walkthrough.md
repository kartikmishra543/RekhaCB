# A distinctive demo story — Request Readiness

Lead with one employee decision: “Can I take these days, and what should my approver know?” Show the request moving from a tentative plan to an evidence-backed, confirmed HRMS record.

## Suggested 8-minute recording

1. **0:00–0:45:** Explain the problem and credit the supplied CB Nest starter. Introduce RekhaCB's planning workflow.
2. **0:45–2:15:** Open Request Readiness. Enter a two-day future leave request. Show calendar-day counting, available/projected balance, policy evidence, pending commitments and approval path. Explain that readiness is not approval.
3. **2:15–3:15:** Pin that option. Change dates or select a half day and run another check. Explain the difference in projected balance. Then try an over-budget date range and show preparation blocked.
4. **3:15–4:45:** Restore a valid plan. Show the approver brief and export a JSON snapshot. Prepare, review and confirm. Open Leaves to verify the real pending record. Check the same dates again and show the overlap warning becomes a blocker.
5. **4:45–6:15:** Switch to Ask the copilot. Ask a policy question with citations, ask for project assignments, and ask for salaries to show a refusal. Use a manager account to show scoped SQL and a real leave approval if time permits.
6. **6:15–7:15:** Explain three boundaries: AI interprets policy/questions, deterministic code evaluates readiness, existing APIs validate and execute writes. Show that a prepared request is rechecked on confirmation.
7. **7:15–8:00:** Show the test results. Discuss the transaction race limitation, local TF-IDF/template mode, provider verification status, and what you would improve next.

Do not describe the snapshot fingerprint as an approval, signature or security certificate. It helps identify the facts used for a review. Avoid unsupported claims that no other student has built something similar.

Keep API keys and tokens off-screen. Use fictional records. Upload the actual recording, verify access, and replace the README video placeholder. Speak from your own understanding and show what you actually tested.

## Questions to prepare for

- Why use explicit checks rather than ask an LLM whether someone is eligible?
- Why do weekends count, and where is that rule inherited from?
- Do pending leaves reserve balance? What happens if another request is approved?
- What changes between analysis, preparation and confirmation?
- What does the fingerprint prove, and what does it not prove?
- Can an admin inspect somebody else's plan in this workspace?
- Which parts came from CB Nest, and which parts were added?
